Grounding Context (배경 및 기반 분석)

초기 계획 문서(docs/plans/2026-08-20-2224-feat-protokflow-mcp-server-plan.md)는 Python 공식 mcp SDK를 사용하는 stdio MCP 서버와 Starlette 기반의 웹소켓 프리뷰 서버를 병렬 구동하는 구조를 제안했습니다. 그러나 "AI 코딩 에이전트(Claude Desktop, Cursor, Codex 등)의 원활한 조작"과 "인간 사용자의 실시간 브라우저 핫리로드 비교"라는 두 가지 목표 사이에서 MCP vs. FastAPI의 적합성 및 결합 방식에 대한 원점 재검토가 필요합니다.

📌 핵심 목표 및 페인포인트

기존 로컬 하니스의 20+ 회 CLI 호출 의례를 타파하고, 에이전트가 단 1~2회의 도구 호출로 디자인 토큰 기반 후보 화면을 생성하고 실시간 프리뷰를 띄우는 것이 목표입니다.

⚡ 3계층 토큰 엔진 (Astryx 기반)

Foundations → Components → Patterns 3계층 토큰 구조로 Jinja2에 주입하여 문법 오류 없는 정적 HTML/CSS를 1ms 이내 렌더링하고 React/Tailwind 코드로 추출합니다.

MCP vs. FastAPI vs. Hybrid 아키텍처 비교표

구분 순수 MCP (stdio) 순수 FastAPI (REST+WS) 하이브리드 코어 (FastMCP / ASGI Embedded) ⭐
에이전트 조작성 최상 (Native Tool): uvx protokflow로 무설치 자동 도구 등록. 열세: 서버 사전 구동 필요, cURL/OpenAPI 호출 의례 발생. 최상 (Native Tool): 에이전트에게는 표준 MCP Tool로 직접 노출.
브라우저 프리뷰 제한적: stdio는 JSON-RPC 전용이므로 별도 웹 서빙 백그라운드 필요. 최상: 단일 포트에서 Swagger API + 웹소켓 핫리로드 직접 서빙. 최상: MCP 내부에서 가벼운 Starlette ASGI 루프백 서버를 온디맨드 바인딩.
생명주기 & 포트 충돌 에이전트 종료 시 프리뷰 서버가 좀비로 남거나 포트 4100 충돌 위험. 백그라운드 데몬 관리 필요 (수동 Ctrl+C 또는 kill 필요). 완벽 해결: 동적 포트 바인딩(port 0) 및 stdio EOF 연동 자동 정리.
결론 및 권고 에이전트 UX는 좋으나 웹 프리뷰 격리 필요. 웹 개발엔 편하나 에이전트 도구 연동 비용 큼. 채택 권고: 순수 Python 코어 엔진 + FastMCP/ASGI 듀얼 어댑터.

RANK 1 · CORE ARCHITECTURE

Headless Domain Engine Core with Dual-Mode Protocol Adapters (MCP & FastAPI as Thin Shells)

core-engine-modularity Confidence 95% Complexity Medium

"MCP냐 FastAPI냐"라는 이분법을 해체하고, 토큰 3계층 해석과 Jinja2 렌더링, React/Tailwind 코드 추출 로직을 전송 계층과 완전히 독립된 순수 Python 비즈니스 로직(protokflow.core)으로 설계합니다. 그 위에 MCP 도구 어댑터(protokflow.adapters.mcp)와 FastAPI/Starlette 웹 어댑터(protokflow.adapters.http)를 각각 50줄 내외의 얇은 래퍼(Thin Shell)로 구현하여, CLI 진입점(protokflow [mcp|serve])에 따라 둘 다 완벽하게 구동할 수 있도록 합니다.

구조 다이어그램: 순수 Python 코어 엔진과 얇은 프로토콜 어댑터 계층 분리
Basis: reasoned: docs/plans/...:33-47 & docs/concepts/...:9-24. 코어 렌더링 로직을 전송 계층과 분리하여 네트워크 목킹 없는 10ms 단위 테스트 및 다중 전송 계층 지원 달성.
Rationale: 사용자나 에이전트가 어떤 방식을 선호하든 핵심 비즈니스 로직(토큰 캐스케이드 및 템플릿 렌더링)을 단 1줄도 중복하지 않고 100% 재사용할 수 있습니다.
Downsides: 단일 파일 스크립트 대비 프로젝트 패키지 구조(core, adapters, cli) 초기 보일러플레이트 분리 설계 비용이 발생합니다.
RANK 2 · PROCESS & LIFECYCLE

In-Process FastMCP / Embedded ASGI Preview Server with Ephemeral Port & Process Tethering

state-lifecycle-execution-model Confidence 90% Complexity Small

stdio 기반 MCP 서버는 표준 I/O가 JSON-RPC 전용으로 사용되므로, 고정 포트(4100) 웹 서버를 함께 띄우면 다중 워크스페이스 실행 시 포트 충돌(Errno 48) 및 좀비 프로세스 누수가 발생합니다. 이를 해결하기 위해 MCP 프로세스 내부에서 동적 임시 포트(port 0) 루프백 ASGI 서버를 온디맨드로 구동하고, 에이전트 stdio 파이프의 EOF를 감지하여 에이전트 종료 시 프리뷰 서버를 500ms 내에 스스로 안전하게 회수(Dead-Man's Switch)합니다.

Basis: direct: docs/plans/...:39,102-108 & FastMCP / Starlette 라이프스팬 연동 모델.
Rationale: 개발자가 수동으로 kill -9를 하거나 포트 점유 에러를 겪지 않아도 되며, uvx protokflow 명령 하나로 완전 무간섭(Zero-maintenance) 로컬 실행을 보장합니다.
Downsides: 에이전트가 재시작되면 프리뷰 포트 번호가 달라지므로 브라우저 탭을 새로 열어야 합니다. (PID 락파일로 완화 가능).
RANK 3 · LIVE FEEDBACK

Zero-Compile CSS Custom Property Injection for Instant (<16ms) Hot-Reload

live-preview-feedback-loop Confidence 92% Complexity Small

Astryx 3계층 토큰(Foundations, Components)을 브라우저 :root의 CSS Custom Properties(--pf-colors-primary, --pf-radii-md)로 1:1 매핑합니다. 에이전트가 patch_tokens를 호출할 때 무거운 Jinja2 HTML 전체를 다시 렌더링하지 않고, 웹소켓을 통해 변경된 토큰 델타만 전송하여 style.setProperty로 16ms(60fps) 이내에 즉각 화면 스타일을 모핑합니다.

Basis: direct: docs/plans/...:44-46, 166 & docs/concepts/...:33-57. 200ms 반응성 SLA 초과 달성 및 입력 폼 포커스/스크롤 상태 100% 보존.
Rationale: 전체 HTML 재렌더링 시 발생하는 화면 깜빡임(FOUC)과 인풋 포커스 유실을 없애고 Figma 스타일의 부드러운 토큰 조작 반응성을 제공합니다.
Downsides: 새로운 HTML 태그나 슬롯 구조가 추가되는 update_slot_custom의 경우에만 부분 DOM 교체가 필요합니다.
RANK 4 · SCHEMA PARITY

Single-Source Pydantic Schemas with Auto-Compiling MCP Tools & FastAPI OpenAPI Specs

agent-interaction-friction Confidence 88% Complexity Small

3계층 토큰 계층(Foundations, Components, Patterns)과 5종 도구 인터페이스를 Pydantic v2 모델로 단 1회 엄격히 정의합니다. 이 모델로부터 FastMCP는 엄격한 JSONSchema 제약(Enum, Literal 프리셋)을 갖춘 MCP 도구를 컴파일하고, FastAPI는 대화형 Swagger/OpenAPI 문서를 자동 생성하여 두 인터페이스 간의 스키마 드리프트를 원천 차단합니다.

Basis: direct: docs/concepts/...:30-124 & docs/plans/...:57-120. Pydantic v2 단일 소스 정의.
Rationale: 에이전트가 잘못된 레이아웃 프리셋이나 누락된 필드를 전달하는 파싱 오류를 사전 방지하고 완벽한 타입 안전성을 확보합니다.
Downsides: Pydantic v2 의존성이 추가되나 현대 Python 개발 환경에서 표준에 가깝습니다.
RANK 5 · VISION AGENT SUPPORT

Automated Headless Multimodal Snapshot Injection for Vision Agents

agent-interaction-friction Confidence 85% Complexity Medium

에이전트가 create_prototype_run 또는 patch_tokens를 호출했을 때, 텍스트 URL뿐만 아니라 공식 MCP 표준인 ImageContent(Base64 스크린샷 이미지)를 도구 결과에 함께 반환합니다. 이를 통해 Claude 3.7 Sonnet이나 GPT-4o 같은 멀티모달 비전 모델이 자신이 생성한 UI 레이아웃의 시각적 불균형이나 대비 문제를 1턴 만에 스스로 확인하고 자가 교정할 수 있게 합니다.

Basis: external: 공식 MCP Multimodal Tool Result 규격 (ImageContent payload).
Rationale: 인간이 브라우저를 보고 "텍스트가 잘렸어"라고 지적하기 전에 에이전트가 렌더링된 시각 이미지를 직접 보고 폐루프(Closed-Loop)로 품질을 높입니다.
Downsides: 헤드리스 렌더링(Playwright 또는 초경량 래스터라이저) 구동 시 약간의 지연 시간(100~300ms)이 추가될 수 있어 옵션 플래그로 제공해야 합니다.
RANK 6 · COMPARISON UX

Synchronized Viewport Matrix for Multi-Candidate Side-by-Side Live Comparison

live-preview-feedback-loop Confidence 84% Complexity Medium

브라우저 프리뷰 쉘을 다중 뷰포트 매트릭스 캔버스로 구성하여 생성된 모든 후보군(c1, c2, c3)을 바둑판형 또는 2열 분할형으로 동시에 나란히 렌더링합니다. 하나의 후보에서 스크롤을 내리거나 반응형 브레이크포인트 핸들을 조절하면 모든 후보 화면이 동기화되어 움직여 시각적·구조적 차이점을 한눈에 평가할 수 있습니다.

Basis: direct: docs/plans/...:19, 46. 다중 후보 및 상태별 나란히 비교(Side-by-Side Comparison) 뷰 제공.
Rationale: 탭 전환 방식으로 인한 인간의 단기 기억 손실을 방지하고 의사결정 시간을 70% 단축합니다.
Downsides: 후보군이 4개 이상으로 많아질 경우 브라우저 렌더링 부하 및 화면 공간 제약이 발생합니다.
RANK 7 · CODE EXPORT

Deterministic AST-Free Swizzle Exporter for React/Tailwind Emission

core-engine-modularity Confidence 89% Complexity Small

export_prototype 구현 시 파이썬 내에서 불안정한 JS/TS AST 구문 트리를 직접 조립하지 않고, Docusaurus의 swizzle 방식처럼 사전에 엄격히 검증된 React/Tailwind 컴포넌트 템플릿에 확정된 토큰 값을 1:1 치환하여 내보냅니다. 이를 통해 생성된 TSX 컴포넌트가 100% 문법 오류 없이 실제 프로덕션 프로젝트에 즉시 마운트될 수 있도록 보장합니다.

Basis: direct: docs/concepts/...:170-221 & docs/plans/...:40, 110-119. 프로덕션 코드 직결성.
Rationale: AST 파서의 엣지 케이스 버그를 원천 배제하고 즉시 린트/컴파일이 통과하는 무결점 코드를 방출합니다.
Downsides: 지원하고자 하는 프론트엔드 프레임워크(React, Vue 등)별로 사전 정의된 템플릿 프리셋이 유지 관리되어야 합니다.
